# 总裁助理直执行与多维表格报告设计

日期：2026-07-29
状态：已确认
适用范围：一位已配对总裁、一台常驻 Mac mini、一个企业自建飞书机器人

## 1. 目标

在现有飞书桥接、Codex、固定飞书 CLI、SQLite 账本和 LaunchAgent 上增加三类高频能力：

1. 总裁在飞书私聊中直接下达日程指令，信息完整时立即创建，不再点击确认卡片。
2. 总裁直接通知一个或多个人，支持文本、展示卡片和飞书附件；全部收件人明确后立即发送。
3. Codex 读取指定多维表格，完成有数据范围说明的分析，并在总裁云空间创建原生飞书云文档报告。

本设计不建设第二套 Agent、工作流平台、后台、数据库服务或常驻进程。

## 2. 选定方案

采用“扩展现有网关”的方案。

```text
已配对总裁私聊
  -> 现有入站校验和任务账本
  -> Codex 自然语言理解
  -> 固定 Gateway read / execute 能力
  -> 固定飞书 CLI route
  -> 飞书结果
  -> 机器人私聊反馈
```

Codex 仍不能直接执行 raw `lark-cli`、飞书 HTTP API、自由 URL、自由 shell 命令或自由选择
Bot/User 身份。所有新增能力必须有严格 JSON Schema、固定身份、固定命令模板、输入上限和结果校验。

## 3. 原始指令即授权

### 3.1 授权来源

只有同时满足以下条件的任务可以进入直执行：

- 入站事件已经通过现有签名、租户、应用、总裁 `open_id` 和绑定私聊校验；
- 任务账本仍处于当前 runtime lease 下的可执行状态；
- 外部动作能够从本次总裁原始指令和本任务已登记输入中完整推导；
- 所有目标人员、时间、正文和附件已经确定。

普通附件、引用内容、云文档和多维表格内容均是不可信数据，不能赋予直执行权限。

### 3.2 网关合同

`GatewayRequest.kind` 增加固定的 `execute` 类型。网关不提供
`skipConfirmation`、`autoApprove` 或任何由模型自由开关的布尔字段。

直执行动作使用新的账本审批模式 `president_instruction`：

- 网关从父任务反查原始入站总裁和私聊，模型不能提交 actor 或 chat；
- 动作 payload、目标、正文、附件引用和身份先 canonicalize 并计算 SHA-256；
- 同一事务写入动作、基于原入站事件的授权证据和
  `NULL -> APPROVED(reason=president_instruction_approved)` transition；
- 后续继续复用现有 `CLAIMED -> DISPATCHING -> SUCCEEDED / FAILED / UNKNOWN`
  状态机、lease、attempt 和 idempotency；
- `UNKNOWN` 永不自动重试。

这会在现有 SQLite 内增加 schema migration 和必要的批次/项目记录，不会增加第二个数据库。

## 4. 联系人解析

### 4.1 固定组织优先级

联系人搜索固定使用 User 身份和企业内人员范围。优先级依次为：

1. 通过 `contact +search-user --user-ids me` 动态取得的总裁当前所属组织；
2. `融创中国-直管业务-文旅事业部`；
3. `融创中国-热雪奇迹`；
4. 全企业其他候选。

部门路径按飞书 CLI 返回的完整 `department` 字符串做规范化子串匹配，不自行构造部门 ID。

### 4.2 自动选择与消歧

- 最高优先级内恰好一个匹配：自动选取。
- 最高优先级内多个同名匹配：返回姓名、部门、企业邮箱等可区分信息，等待总裁选择。
- 三个优先组织均无匹配：继续搜索全企业，但只展示候选，不自动向该范围人员发送。
- 搜索结果 `has_more=true`：收紧姓名、邮箱或组织条件；不得把首屏当作完整候选集。
- 总裁补充选择后只补齐人员，不再询问“是否执行”。

动作网关只接受由本任务联系人解析结果导出的收件人引用或解析条件，不接受模型自由提供的
`open_id`。

## 5. 日程直执行

新增固定 `calendar.create.direct` 能力，使用 User 身份和总裁主日历。

### 5.1 默认值

- 时区固定为 `Asia/Shanghai`；
- 只创建单次日程；
- 开始时间明确但未提供结束时间时，默认持续 1 小时；
- 未提供参会人时，只创建总裁自己的日程；
- 提供参会人姓名时，按第 4 节解析并邀请；
- “明天下午”“下周找个时间”等没有明确开始时间的表达只追问具体时间；
- 补齐缺失信息后立即创建，不再生成确认卡片。

时间转换必须由确定性代码完成。开始时间必须真实存在、尚未完全过去且早于结束时间。

### 5.2 结果边界

只根据固定版飞书 CLI 的真实请求和返回汇报标题、开始/结束时间、参会人和远端日程标识。
本轮不承诺 CLI 未显式支持的视频会议、提醒、忙碌状态或参会人编辑权限，也不实现改期、取消、
重复日程和会议室。

## 6. 通知直执行

新增固定 `notification.send.direct` 能力，使用 Bot 身份，仅面向内部个人，不支持群聊。

### 6.1 内容形态

- 简短内容默认发送纯文本；
- 有标题、事项、时间、附件或多人收件人时默认发送展示型 Schema 2.0 卡片；
- 总裁明确要求“用卡片发”时使用卡片；
- 卡片由网关固定模板生成，只允许标题、来源、正文、事项列表和附件入口，不接受任意卡片 JSON；
- 卡片不包含确认、审批或其他 callback 按钮；
- 总裁明确要求“原话转发”时正文保持原样；否则 Codex 可以整理措辞但不能改变原意。
- 带附件时先向每名收件人发送一张列出文件名的通知卡片，再逐个发送原附件；卡片本身不伪装成
  已发送文件。

### 6.2 多人发送

- 单次最多 20 名内部个人收件人；
- 网关在任何发送前解析全部收件人；
- 任一收件人重名、缺失或不在允许范围时，整批零发送；
- 全部明确后按稳定顺序逐人发送；
- 每名收件人拥有独立 action item、idempotency key、attempt 和结果；
- 同一收件人的卡片和附件属于同一 delivery item，分别记录远端结果；
- 某一项明确失败时继续处理后续已解析项；
- 已成功项不重发，最终向总裁返回成功、明确失败和结果不确定三组名单。

### 6.3 附件

只允许以下附件：

- 当前总裁私聊入站事件中由 runtime 登记的附件；
- 总裁明确回复引用的飞书消息中由 runtime 重新核验并登记的附件。

网关使用 task file/resource reference，不接受绝对路径、`..`、任意本机路径、任意 URL 或模型提供的
file key。原文件和文件名保持不变。适配器根据已核验资源使用固定的飞书文件发送或消息转发 route。

本轮不从 Mac 任意目录挑选文件，不转发群消息，也不创建群。

## 7. 多维表格读取

新增以下只读能力，全部使用 User 身份和固定 `lark-cli base +...` shortcut：

- `base.resolve`：严格解析飞书 Base/Wiki URL，或按不超过 30 个字符的标题关键词搜索；
- `base.schema.read`：读取 Base、数据表、字段和视图的真实结构；
- `base.records.read`：按真实表/视图、字段投影、筛选和排序读取记录；
- `base.data.query`：执行经过严格 Schema 校验的云端聚合、分组、排序和 Top N。

### 7.1 目标确定

- URL 含 table/view 时按该范围读取；
- 只有 Base 且存在多张表时让总裁选表；
- 标题搜索出现多个结果时让总裁选择；
- 不把完整 URL、Wiki token 或孤立 token 直接当 `base_token`；
- 不允许 raw API path 或 Base 写操作。

### 7.2 数据完整性

- 单次底层分页不超过 CLI 允许的 200 条；
- 每个任务每张表最多向 Codex 暴露 2,000 条原始记录或 8 MiB 结构化输出，以先达到者为准；
- 能在云端完成的筛选、排序、聚合、分组和 Top N 必须用 `base.data.query`；
- `has_more=true`、分页未完成或达到原始记录上限时，不得声称全量；
- 需要全局结论但原始行过多时，使用云端聚合，并在报告写明表、视图、时间范围、过滤条件和聚合口径；
- 权限、字段、视图或分页链路失败时，不把失败解释为空数据。

## 8. 飞书云文档报告

新增固定 `document.report.create` 能力，使用 User 身份在总裁 `my_library` 创建原生飞书云文档。

Codex 提交结构化报告对象，网关负责渲染为受限 Docx XML；不接受自由 CLI flag、任意
`parent_token`、任意本地文件或任意 XML。报告至少包含：

1. 核心结论；
2. 关键数据；
3. 异常与风险；
4. 建议动作；
5. 数据来源、范围、过滤和聚合口径。

标题格式为“`<多维表格名称>分析报告｜YYYY-MM-DD`”。成功后机器人私聊只发送一至三句核心结论
和飞书云文档链接，不生成 Markdown、PDF 或 PPT 附件。

创建文档是本次总裁“汇总并给我报告”原始指令授权的直执行动作。创建结果不确定时不自动重试。

## 9. 最小权限与一次点击授权

在现有权限基础上只增加本设计所需权限。

### 9.1 User 身份

- `base:app:read`
- `base:table:read`
- `base:field:read`
- `base:view:read`
- `base:record:read`
- `base:record:retrieve`
- `search:docs:read`
- `docx:document:create`

不申请 Base create/update/delete、文档编辑/删除或云盘管理权限。

### 9.2 Bot 身份

继续使用 `im:message:send_as_bot`，并为核验、转发和发送已登记附件增加当前固定 route 实际要求的
`im:message:readonly`、`im:message` 和 `im:resource`。不申请群管理、群成员管理、撤回或加急权限。

### 9.3 授权体验

- installer、updater 和 `doctor` 校验精确权限集合；
- 缺 User scope 时，runtime 使用固定授权 helper 生成一次性授权 URL；
- 机器人在总裁私聊发送一张仅含授权链接的卡片，总裁可直接在手机飞书点击；
- helper 在内存中做一次有界设备授权轮询，不把 URL、device code 或 token 写入日志、任务正文或
  Codex prompt；
- 授权成功后提示总裁重新发送原任务；
- 缺开发者后台权限时不循环 OAuth，停止任务并通知交付人员处理。

## 10. 失败语义

对总裁只输出以下三类业务结果：

- **未执行**：信息缺失、人员未解析、权限不足或飞书明确失败；说明没有产生外部影响。
- **部分完成**：多人通知部分成功；列出成功、明确失败和不确定对象，成功对象不重发。
- **结果不确定**：远端调用超时、连接断开或本地最终落账失败；不自动重试，并说明应检查的飞书对象。

多维表格读取在权限、字段或分页链路中断时不创建报告。达到明确原始记录上限但能够取得可信云端
聚合时，可以创建报告，但必须在文档首屏注明数据范围。

错误回复不得包含命令、堆栈、token、完整人员 ID、客户正文或原始飞书错误对象。

## 11. 验收

### 11.1 自动化

必须至少覆盖：

- 只有配对总裁私聊可以使用 `execute`；
- 模型不能提交 actor/chat、自由 ID、自由路径、自由 card JSON 或 raw API；
- 日程无需卡片直接执行且同一任务恰好一次；
- 1 小时默认时长、上海时间和模糊时间补问；
- 动态所属组织、两个固定组织、同级重名和全企业兜底；
- 多人解析失败时整批零发送；
- 文本、固定卡片、20 人上限和任务附件引用；
- 多人发送部分失败、`UNKNOWN` 和重启恢复不重发成功项；
- Base URL/标题、表/视图消歧、字段读取、分页、2,000 行上限和云端聚合；
- 截断数据不能产生伪全量结论；
- 原生飞书云文档创建和链接回传；
- 缺 User scope 的一次点击授权卡片与缺后台权限的明确停点；
- updater、installer、doctor 和旧安装升级兼容。

### 11.2 本地与真实飞书

1. 先通过 format、lint、typecheck、build、全仓测试和固定 CLI dry-run。
2. 在模拟 adapter 中完成全矩阵，不调用真实飞书写操作。
3. 单独取得用户授权后，使用明确的测试人员、测试日程、测试附件和测试 Base 做真实验收。
4. 真实验收至少覆盖一次日程、一次单人文本、一次多人卡片、一次附件、一次 Base 读取和一次云文档。
5. 所有功能通过后更新 README/CHANGELOG，再单独申请本地提交和公开 `main` 推送授权。

## 12. 明确不做

- 不做群聊发送、建群或群管理；
- 不做日程修改、取消、重复日程、会议室或自动找空闲时间；
- 不做 Base 写入、表/字段/视图修改或自动订阅；
- 不从 Mac 任意目录挑选附件；
- 不创建或更新已有飞书云文档，只创建本次报告的新文档；
- 不做定时报告、主动推送或后台看板；
- 不新增守护进程、远端服务、第二个数据库、管理界面、PR、Tag 或 Release 流水线。

## 13. 发布边界

实现必须从当前公开 `origin/main` 的独立 `codex/` feature branch 开始。复杂发布流水线旧工作树保持
停用，不作为实现基础。

规格确认不等于代码实现、本地提交、真实飞书写入或 GitHub 发布授权。每个门禁继续独立：

1. 规格文件；
2. 实施计划；
3. 本地实现与模拟测试；
4. 真实飞书验收；
5. README/CHANGELOG；
6. 本地提交；
7. 非强制推送公开 `main`。
