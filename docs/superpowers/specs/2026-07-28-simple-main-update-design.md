# 总裁助理最小更新设计

日期：2026-07-28
状态：已确认
原则：只解决“一位总裁、一台 Mac mini、无需碰终端即可更新”

## 1. 选定方案

采用 GitHub `main` 直连更新，不建设独立 Release 系统。

机器人每次收到已配对总裁的私聊时，若距离上次检查已满 24 小时，就自动检查公开仓库
`banqiusheng/codex-feishu-executive-assistant` 的 `main` 是否出现新 commit。

- 没有更新：正常处理总裁任务，不增加提示。
- 有更新：在正常回复末尾提示“发现新版本，回复‘更新’即可安装”。
- 总裁回复“更新”：机器人执行更新；其他文字不触发安装。

自动检查采用“使用时检查”，不增加第二个 LaunchAgent，也不在无人使用时主动打扰总裁。

## 2. 更新动作

新增一个固定更新入口，由 `executive-assistant` Skill 直接调用，不允许模型自由拼接 Git
或安装命令。

更新入口只做下面六步：

1. 核验当前目录是预期 GitHub 仓库，且工作区没有用户改动。
2. 获取远端 `main`，只接受 fast-forward。
3. 记录更新前 commit。
4. 快进到新 commit。
5. 复用现有安装链的内部非交互入口 `./scripts/install --update-existing`
   完成构建、安装和 LaunchAgent 重启；沿用既有 App ID、Keychain 和用户授权。
6. 安装失败时恢复更新前 commit，并尝试恢复旧版本；不继续叠加修复。

机器人在开始前回复“收到，开始更新，预计需要几分钟”。更新期间允许机器人短暂离线；
LaunchAgent 会重新拉起服务。总裁不需要复制命令、链接或打开终端。

## 3. 最小状态

只在 `~/PresidentAssistant/runtime/` 保存一个权限为 `0600` 的非敏感状态文件：

- 上次检查时间；
- 当时看到的远端 commit；
- 是否提示过该 commit。

状态文件不保存 GitHub Token、飞书凭据、客户正文或人员信息。公开仓库不需要 GitHub Token。

## 4. 失败处理

- GitHub 暂时不可达：不影响总裁当前任务，不反复提示。
- 仓库有本地改动、远端不能 fast-forward、安装失败：停止更新，保留或恢复旧版本。
- 更新后的机器人无法重新上线：交付人员运行现有 `./scripts/doctor`；不新增另一套 doctor。

## 5. 验收

只验证四件事：

1. 24 小时内重复私聊不会重复访问 GitHub 或重复提示。
2. 发现新 commit 后，回复末尾只出现一次更新提示。
3. 非“更新”消息不会安装；总裁明确回复“更新”才执行。
4. 在本地临时 Git 仓库中验证 fast-forward 成功、脏工作区拒绝、非 fast-forward 拒绝和安装失败恢复。

## 6. 明确不做

- 不做 GitHub Release、Tag、manifest、签名、keyring、校验和服务。
- 不做 arm64/x64 双架构发布包或可复现 tar。
- 不新增网关能力、数据库表、后台平台、管理页面或第二个守护进程。
- 不自动安装，不静默改版本，不让总裁操作终端。
- 不把当前未完成的复杂发布流水线代码带入实现。

## 7. 实施边界

实现从干净的 `origin/main` 新分支开始，仅增加最小更新入口、Skill 路由、必要的安全环境值
和聚焦测试。当前复杂发布流水线工作树保持停用，不提交、不推送，也不作为新实现基础。

Runtime 只向 Codex 子进程增加已配置 Node、仓库根目录和运行时目录三个非敏感固定路径；
不传递 App Secret、Token、自由参数或新的外部能力。

已安装旧版本第一次取得本功能时，由该 Mac 上的 Codex 在确认工作树干净后仅
fast-forward 到公开 `main`，再运行一次 `./scripts/install --update-existing`。此后不再
需要交付人员操作。
